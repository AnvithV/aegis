Queries

Queries are the core resource. Submitting a query kicks off the full ingestion and ranking pipeline asynchronously and returns a job_id immediately.

POST /v1/queries​

Submit a new expert-discovery query. Returns a job_id immediately (HTTP 202); the pipeline runs in the background.

Auth required: Yes

Request Body​

{
  "task_description": "KRAS G12C inhibitor medicinal chemist with ADMET experience",
  "k": 20,
  "mesh_override": ["Neoplasms", "Proto-Oncogene Proteins p21(ras)"],
  "cohort_filter": null,
  "cutoff_strategy": "top_k",
  "score_threshold": null,
  "include_variance_bands": true
}
FieldTypeRequiredDefaultDescription
task_descriptionstring✅—Natural-language description of the expertise needed. Minimum 10 characters. Drives MeSH expansion, query classification, and topical-fit scoring.
kinteger❌50Number of ranked candidates to return. Range: 1–500.
mesh_overridestring[]❌nullExplicit MeSH terms to use instead of automatic expansion. If provided and non-empty, LLM/MetaMap expansion is skipped entirely.
cohort_filterstring❌nullRestrict scoring to a specific candidate cohort. Must be in the token's allowed_cohorts if that field is set.
cutoff_strategy"top_k" | "score_threshold"❌"top_k"How to cut the result set. top_k returns exactly K results. score_threshold returns all candidates above score_threshold up to K.
score_thresholdfloat❌nullRequired when cutoff_strategy is "score_threshold". Candidates with composite score below this value are excluded.
include_variance_bandsboolean❌trueWhether to compute bootstrap variance bands (200 Monte Carlo samples). Adds ~0.5 s to pipeline runtime.

Response — 202 Accepted​

{
  "job_id": "a3f2c1d0e8b947f6a2c3d4e5f6a7b8c9",
  "status": "in_progress"
}

Use the job_id to poll GET /v1/jobs/\{job_id\} or stream progress from GET /v1/queries/\{job_id\}/stream.

Errors​

StatusCondition
400task_description shorter than 10 characters, or k out of range
401Invalid or missing token

POST /v1/queries/classify​

Classify a query and return the detected query type, confidence score, matched keywords, and the weight vector that would be applied. This is called live by the frontend as you type (debounced at 300 ms) to power the query-type badge and weight-slider preview.

Auth required: Yes

Request Body​

{
  "task_description": "Phase 2 clinical trial investigator for KRAS lung cancer"
}

Response — 200 OK​

{
  "query_type": "clinical_trial_pi",
  "confidence": 0.8,
  "keyword_matches": ["clinical trial", "phase 2"],
  "weights": {
    "f1_rcr": 0.15,
    "f2_funding": 0.10,
    "f3_leadership": 0.25,
    "f4_apex": 0.05,
    "f5_translational": 0.15,
    "f6_lineage": 0.05,
    "f7_clinician": 0.25
  },
  "exponents": {
    "alpha": 0.7,
    "beta": 1.0,
    "gamma": 0.4
  }
}
FieldDescription
query_typeOne of basic_research, drug_discovery, clinical_trial_pi, policy_epi
confidence0.5 when no keywords match (default fallback); increases by 0.1 per matched keyword, capped at 0.95
keyword_matchesThe specific keyword strings from the query that triggered the classification
weightsF1–F7 family weights for the selected weight vector. Sums to 1.0.
exponentsDefault α (quality), β (topical fit), γ (recency) for the ranking formula

Query Types​

TypeTriggered byDominant weight
basic_researchDefault — no matching keywordsF1 RCR (40%)
drug_discoveryinhibitor, ic50, sar, admet, compound, lead optimization, …F5 Translational (50%)
clinical_trial_piclinical trial, phase 2, randomized, irb, enrollment, …F3 Leadership + F7 Clinician (25% each)
policy_epiepidemiology, incidence, prevalence, social determinants, …F1 + F3 Leadership balanced

component_scores fields​

KeyMeaning
QQuality percentile (composite of F1–F7 weighted by the selected vector)
TTopical fit (0–1, how well the candidate's evidence matches the query)
RRecency (0–1, decaying over 5 years from last source update)
IIntegrity (1.0 unless a hard-gate rule zeroed this candidate)

Errors​

StatusCondition
404No query with that ID exists, or it belongs to a different customer

GET /v1/queries/{query_id}/stream​

Stream real-time source-fetch progress as Server-Sent Events. Connect immediately after submitting a query to see each data source report in as it finishes.

Auth required: Yes (token sent in header, not URL)

Path Parameters​

ParamDescription
query_idThe job_id returned when the query was submitted

Event Types​

source_progress​

Emitted once per data source as soon as that source finishes fetching. Sources run in parallel so events arrive out-of-order and in quick succession.

event: source_progress
data: {"source_name":"pubmed","status":"complete","record_count":200,"latency_ms":4312.5,"error":null}
event: source_progress
data: {"source_name":"ctgov","status":"failed","record_count":0,"latency_ms":1200.0,"error":"HTTPStatusError: 503"}
FieldDescription
source_nameOne of pubmed, reporter, ctgov, openalex_works
status"complete" or "failed"
record_countNumber of records fetched (capped at 200 per source)
latency_msWall-clock time for the fetch
errornull on success; error string on failure

complete​

Emitted when the entire pipeline finishes (all sources ingested, scoring and ranking done, results written to DB).

event: complete
data: {}

After receiving complete, call GET /v1/queries/\{query_id\} for the full results.

timeout​

Emitted if no events arrive within 300 seconds (should not occur in normal operation).

event: timeout
data: {}

Notes​

  • The SSE queue is pre-created when POST /v1/queries is called, so events are buffered even if the client hasn't connected yet. Connecting immediately after the 202 response guarantees no events are missed.
  • The Vercel proxy route for this endpoint has maxDuration = 300 to support pipelines that take up to 5 minutes.
  • On error (EventSource fires onerror), the pipeline continues running; poll GET /v1/jobs/\{job_id\} to check final status.
