# Phase-by-Phase Overview

Aegis was built incrementally across five phases, each adding a distinct layer of capability. Later phases depend on earlier ones, and each phase was validated against specific exit criteria before the next one began.

## Phase 0 — Foundation

**What it built:** The data substrate that everything else depends on. Phase 0 delivered three public-source ingestion clients (PubMed, NIH RePORTER, ClinicalTrials.gov) with rate-limit-safe, cursor-based incremental refresh. It built the two-tier identity resolution pipeline — deterministic matching via ORCID and eRA Commons, probabilistic Fellegi-Sunter linkage for records without strong keys — that produces unified candidate profiles in a DuckDB analytical store. It assembled the first seed cohort: NSCLC translational researchers, validated against four archetypes representing distinct researcher profiles.

**What it unlocked:** A working pipeline from raw public data to unified candidate records, proving that Aegis could ingest, deduplicate, and store the data substrate that scoring would consume. The archetype validation harness established the pattern used throughout later phases to verify that system behavior matches expectations.

## Phase 1 — Scoring

**What it built:** The full scoring and ranking engine. Phase 1 delivered six quality-prior sub-scores (F1 through F6) covering citation impact, funding trajectory, leadership, apex-list membership, translational output, and academic lineage — composed via weighted geometric mean into the quality prior Q(c). It added the integrity gate with hard disqualifiers (retraction, ORI, OFAC/SAM, LEIE) and soft discounts (predatory journals, paper-mill indicators). It built query-dependent topical fit via MeSH vector similarity and recency via exponential time decay. The end-to-end ranker composes these into the final score. Phase 1 also delivered the audit harness for collecting pairwise expert judgments, the Plackett-Luce weight learning pipeline, and observability infrastructure including score distribution monitoring, integrity hit-rate tracking, and weight stability alerting.

**What it unlocked:** The ability to take a specialty query and produce a defensible, transparent, ranked list of researchers — with every score broken down by component and every integrity decision logged. The weight learning pipeline meant rankings could improve over time rather than relying on hand-tuned parameters.

## Phase 2 — Multi-Population

**What it built:** Support for three distinct researcher populations. Drug-discovery coverage came through USPTO, EPO, and WIPO patent ingestion, CPC-to-MeSH crosswalks for patent topic mapping, and ChEMBL integration for chemical biology activity. Clinician coverage came through NPI/NPPES provider data, ABMS board certifications, state medical board licenses (10 states), USNWR hospital tier rankings, and CMS Medicare utilization data. Phase 2 added the F7 clinician-specific sub-score synthesizing board certification, license status, hospital tier, trial PI roles, and procedure volume. It delivered per-population weight vectors (translational, drug-discovery, clinician) each learned independently, a specialty classifier for automatic population routing, and cross-population identity merge to handle researchers who span population boundaries.

**What it unlocked:** Aegis went from a single-population translational engine to a multi-population system that could rank drug-discovery scientists, clinicians, and translational researchers using population-appropriate evidence and weights.

## Phase 3 — Production

**What it built:** The operational surface needed to run Aegis as a production service. Phase 3 delivered a FastAPI-based customer query API with JWT authentication, rate limiting, audit logging, and evidence-trail responses. It implemented event-driven integrity ingestion with sub-6-hour latency for critical sources (Retraction Watch, ORI, OFAC/SAM, LEIE) and daily preprint ingestion (bioRxiv, medRxiv). The downstream-task-quality feedback loop ingests Fleiss kappa, accept rate, and consensus rate from customer labeling tasks and feeds them into weekly Plackett-Luce weight relearning. Geographic broadening added seven international source clients (WIPO, ERC, Horizon Europe, MRC, CIHR, JST/KAKEN, NSFC) with per-region coverage diagnostics and a 40%+ non-US target. The contestability workflow allows integrity decisions to be challenged and overridden with evidence.

**What it unlocked:** Aegis became a live production service with an API that customers can query, a feedback loop that continuously improves rankings from real-world outcomes, and international coverage that reduces US-centricity in candidate pools.

## Phase 4 — Frontend (In Progress)

**What it built:** A Next.js web frontend providing a user interface for task managers to interact with Aegis. The frontend includes three core screens: New Query for submitting specialty ranking requests, Results for viewing and exploring ranked candidate lists with score breakdowns, and Query History for reviewing past queries and their outcomes. The documentation site (what you are reading now) was also built in Phase 4.

**What it unlocked:** Task managers can interact with Aegis through a browser rather than making direct API calls, lowering the barrier to use and making score breakdowns, evidence trails, and integrity flags accessible through a visual interface.
